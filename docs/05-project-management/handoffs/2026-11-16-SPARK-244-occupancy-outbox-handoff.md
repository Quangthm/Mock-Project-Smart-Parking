## Recommended owner actions

1. **Operations and Facility owners inventory legacy delivery before retiring the relay.** Count unpublished rows, including leased rows, by type and age. Check queue counts, actual bindings, external users, and older instances in each affected environment. Reconcile any backlog with current state before replay. Preserve event IDs and sequence numbers for safe messages, verify the receiver effect, and agree how to archive messages that would be unsafe to apply. In particular, verify that an old release cannot free a slot reoccupied by another session. [Facility receipts, watermark, and release ledger](../../../src/Services/FacilityService/SmartParking.FacilityService.Persistence/OccupancyProjectionRepository.cs#L18)
2. **Operations retires the legacy relay in a code-only slice once the inventory clears.** Remove `OccupancyOutboxWorker`, the raw publisher and options, the store and ports, the legacy message and row model, their DI/EF wiring, and their worker-only SignalR adapter. Keep the authorized hub and snapshot reconnect behavior. Keep the legacy SQL, existing tables and broker bindings available through cutover so rollback can restore the old binary. Facility should retire its consumer only after its own drain and publisher checks. Agree on schema and topology cleanup separately. [Operations DI](../../../src/Services/OperationService/SmartParking.OperationService.Infrastructure/InfrastructureDependencyInjection.cs#L81) · [EF mapping](../../../src/Services/OperationService/SmartParking.OperationService.Persistence/ReservationDbContext.cs#L57) · [Provisioning checks](../../../scripts/apply-workflow-migrations.ps1#L43)
3. **Monitoring owners verify cross-client refresh and add a replacement only where needed.** If a second authorized operator does not see committed changes until reconnect, evaluate a site-scoped snapshot invalidation using the existing Operations EF outbox and SignalR hub. Invalidate when the read source can reflect the change. If a proven legacy subscriber requires state-bearing events, preserve the raw wire contract and business identity or agree a compatibility transition. MassTransit handles transport persistence and delivery. Per-site sequencing, application deduplication, release-once logic, and SignalR remain separate responsibilities. [MassTransit registrations](../../../src/Services/OperationService/SmartParking.OperationService.Infrastructure/Reservations/ReservationMessaging.cs#L120) · [Frontend replay guard](../../../FE/src/lib/realtimeIdempotency.ts#L44)
4. **Parking Operations resolves settlement versus departure as a separate change.** Align gate checkout with the current rule that only authoritative physical departure releases occupancy. Verify settlement independently and retain the reservation deposit confirmation behavior. [Operations requirements](../../01-requirements/srs/modules/05-sessions-operations.md#L27)
