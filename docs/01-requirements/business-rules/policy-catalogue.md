# Policy catalogue — v1.1

**Normative conventions for every entry:** Unset inherits only where the declared hierarchy permits; disabled is explicit, never numeric zero. Entries marked required prevent product activation until configured. All values are resolved by the listed service; backend accepted timestamps and stored lot timezone govern operational terms (monthly contract preserves its original timezone; cancellation daily counter explicitly Asia/Ho_Chi_Minh). Persist policy ID/revision, valid-from, actor/scope and the resolved value/reference on accepted transactions. Revisions affect future applicable transactions only. Admin defaults/bounds → permitted Owner/lot override → supported specific scope → immutable accepted context. Locked means no newly invented configurable range; visibility in UI grants no editing power. Technical/provider limits validate representability without silently creating a business ceiling.

**Boundary elaborations:** minimum/maximum/horizon are inclusive against the authoritative decision timestamp; this is an explicit RC contract interpretation of approved min/max/horizon, not a new numeric limit. Ordinary hold races use ordered expiry/confirmation; monthly activation and offer acceptance retain their separately approved strict inequalities.

## SEC-01/SEC-02 security catalogue

All entries are owned by User & Access, platform/account scoped, never Owner-configurable. Record effective security-policy version, purpose, account/factor/security version and backend expiry on each challenge. Unset numeric technical parameters fail deployment validation; they do not mean unlimited retries or indefinite validity. Existing primary OTP/token values remain unchanged. **Product choices are confirmed; numeric technical settings below require security implementation review, not invented PM-approved values.**

| Key | Type/value | Authority / bounds / acceptance |
|---|---|---|
| TOTP_ENABLED | Boolean, default false; optional for Driver/Operator/Owner/Admin | Account holder verified enrollment; no automatic role mandate |
| TOTP_DIGITS | 6 digits | Confirmed proposed flow; preserve leading zeroes |
