# Test-to-Requirement Traceability

[Acceptance scenarios](acceptance-scenarios.md) specify expected behavior; all remain **NOT RUN**.
[v1.1 decision coverage](../../01-requirements/requirements-traceability/v1.1-decision-coverage.md) maps each approved V11/D decision to canonical clauses, API/architecture changes and scenarios. [The FR matrix](../../01-requirements/requirements-traceability/matrix.csv) retains requirement/rule/use-case/story associations.

Approval, API design, implementation commit and executed evidence are separate statuses. Blank/unresolved wire details are design work, not proven behavior. Historical reports/evidence under the testing area retain their original dates and results; they do not establish v1.1 acceptance.
