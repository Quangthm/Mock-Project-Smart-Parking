## Acceptance scenarios

| ID | Scenario | Required outcome | Result |
|---|---|---|---|
| AF-001 | Invalid signature/key/issuer/audience/algorithm, expired JWT, missing/malformed actor claims or client-selected actor ID | Protected endpoint fails closed through authentication/policy; no handler business effects. ICurrentActor uses validated claims and performs no network/current-store authorization itself. | NOT RUN |
| AF-002 | Account/role changes after token issuance on a TOKEN operation | Remaining 15-minute token-time freshness may be accepted; no UserService call solely for freshness. Own-resource/scope and domain guards still deny unrelated resources. Expired token fails authentication. | NOT RUN |
| AF-003 | UserService local security write or refresh with stale/ineligible local authority | Authoritative local admin/target/session/credential checks reject as required; no distributed Saga merely for local checks. Refresh never renews solely from stale access claims. Existing local security/factor version guards remain. | NOT RUN |
| AF-004 | Review each six REQUEST families, ordinary TOKEN operations and machine/public/authentication variants | Exact matrix mapping recorded; no HTTP-method/financial/admin heuristic, fabricated customer actor, unapproved feature or permission. New-plan enrollment differs from renewal/change/cancel. | NOT RUN |
| AF-005 | REQUEST admission commits, rolls back or crashes before broker delivery | Pending intent and outbox are atomic; client sees pending, never final confirmation. No synchronous UserService freshness call; no unapproved HTTP-handler speculation. Recovery preserves admitted work; rollback dispatches no effect. No bearer JWT/refresh secret in durable state/messages/logs. | NOT RUN |
| AF-006 | Approved speculative branch finishes before/after authorization; ALLOW arrives before/after prerequisites | Both valid orders converge from durable branch state. Only explicitly approved reversible work can precede Allowed; finalization requires current accepted Allowed plus all prerequisites. No capacity hold is enabled merely by this test. | NOT RUN |
| AF-007 | DENY arrives with no effect, committed reversible effect, in-flight effect or unknown effect; late success follows | Persist cancellation intent; reject, compensate or reconcile according to actual state. Do not declare clean cancellation while unresolved effects remain; never delete physical/financial/history facts or resurrect terminal work. | NOT RUN |
| AF-008 | Missing authorization reply, dependency fault, denial, invalid contract and stale earlier ALLOW | Three logical evaluations maximum, 5-second reply timeout each, 10/30-second waits, 90-second overall deadline; fresh attempt ID per new evaluation, stable ID for its duplicate. At most six planned consumer executions with one 250-ms retry and no stacked delayed redelivery. Old attempts cannot advance state; denial is not retryable; dependency exhaustion is unavailable, never guessed allow/deny. | NOT RUN |
| AF-009 | Retryable ordinary internal consumer fails and restarts | Default 2-second internal call timeout, one retry after 250 ms, two middleware redeliveries after 10/30 seconds: six planned executions, 90-second deadline from first attempt not reset on restart. Filter deterministic errors; 429 only within remaining deadline. Unplanned duplicate deliveries remain idempotent. Overrides documented and tested. | NOT RUN |
| AF-010 | Effect commits but reply is lost; status NotFound/Processing/Unknown; compensation reply lost | Reuse original effect ID; reconcile at +0/+5/+20 seconds, up to three reads with 2-second timeout and 60-second deadline. Unresolved becomes AwaitingReconciliation/ManualReviewRequired, not false failure or a new mutation. NotFound proves no effect only under the ADR's stronger owner guarantee. Compensation has its own stable ID. Retain effect idempotency at least seven days after terminal resolution or longer per provider/business horizon; later replay requires reconciliation. | NOT RUN |
| AF-011 | Original JWT expires or exact initiating session is revoked after admission; Account/role later changes | Expiry/session-only revoke does not itself invalidate Account-current Saga. UserService checks current User/Account/role. Post-ALLOW revocation follows the explicitly accepted per-state race/pivot policy, not an invented COMMIT/WORKFLOW guarantee. | NOT RUN |
| AF-012 | Backend commits revocation; connected/disconnected clients; multiple User/Account/session connections | Backend targets affected connections. Client clears credentials/state/caches, stops authenticated reconnect and redirects safely without normal logout against revoked session. Missing notification does not alter TOKEN stale window; refresh/local checks and REQUEST authority still apply. No single-instance scale-out claim. | NOT RUN |
| AF-013 | Assistant invokes business action; forged service authorization outcome or replayed provider callback | Assistant inherits underlying freshness and confirmation requirements. Broker/service/provider trust and attempt/idempotency checks reject forged/replayed authority; raw user tokens are not propagated as a substitute. | NOT RUN |
| AF-014 | Account becomes locked during user checkout; operational/device exit and payment facts continue | Apply the separately approved safety/obligation contract: no physical stranding, invented customer actor, erased debt or speculative irreversible payment/barrier action. Missing detailed safety design blocks implementation/acceptance of that path, not unrelated work. | NOT RUN |

Real PostgreSQL/broker tests are necessary when claims depend on concurrency, outbox atomicity, routing, restart or delayed delivery. Pure state tests can cover deterministic joins; they do not prove transport durability. Numeric defaults are approved engineering budgets, not measured latency promises or a replacement for Payment's existing business-attempt limits.
