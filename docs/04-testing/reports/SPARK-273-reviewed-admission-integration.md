The app enables new admission only with all its prerequisites configured. The opt-ins default to false. Set `SMARTPARK_RESERVATION_USER_BROKER_USER/PASSWORD`, `SMARTPARK_RESERVATION_OPERATION_BROKER_USER/PASSWORD` and `SMARTPARK_RESERVATION_FACILITY_BROKER_USER/PASSWORD` to the corresponding test identities. Applying configuration to a deployed service, actual TLS and key rotation require operator verification.

The verified fixture used a separate vhost, separate broker users and endpoint-scoped permission patterns for the named [owner queues](../../05-project-management/handoffs/2026-11-18-SPARK-273-reservation-owner-handoffs.md#owner-queues-and-broker-trust), the private Saga/evaluation/progress queues and reservation hold/payment endpoints. The two Account access receive endpoints also declare and bind MassTransit type exchanges. User needs `SmartParking.Contracts.AccountAccess:AccountAccessRequestV1` and Operations needs `SmartParking.Contracts.AccountAccess:AccountAccessDecisionV1` per that topology. Without those permissions the account queues showed zero consumers even though all health endpoints returned 200. Adding the named exchanges to the fixture ACLs resolved that failure. Check actual queue consumers, scoped sends and replies, error/skip transports, and forbid unauthorized publishers before production activation. Fixture restrictions do not certify deployed ACLs.

Fresh PostgreSQL initialized from the owning scripts. User uses `01`, Facility `02` plus `03a`, Operations `03b`, and Payment `04`. Omitting `03a` locally reproduced Facility's missing `structure_backup_policies` and a fail-closed quote 503. Loading that standard bootstrap into the disposable Facility database resolved it. Each application used a non-owner runtime login in its own database. The opposite Operations/Payment CONNECT checks returned false.

For a populated environment, inventory booking/receipt/Saga constraints and nullable legacy terms fields in Operations, and the reviewed evidence, method/currency, fence, provider and reconciliation fields in Payment. The checked-in base `CREATE TABLE IF NOT EXISTS` declarations leave already-existing tables intact. The owners still need to approve and rehearse an additive transition and rollback with populated data, in-flight work and old binaries.
