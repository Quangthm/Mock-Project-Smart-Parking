# SmartParking UI refinement — 23 October 2026

Scope: FE presentation only. The API, routes, data shapes, booking, details, and directions flows were not changed.

## Design and accessibility audit

| Finding | Change | Verification |
| --- | --- | --- |
| Map labels looked angular and some drifted from their geographic point at zoom levels | Rounded labels, a visible geographic tip, removed per-lot pixel offsets, and kept MapTiler `setLngLat` anchors | Three markers stayed inside the map viewport at 375, 768, and 1440px; geographic anchoring preserved on zoom |
| Search Parking and Map type controls had different dimensions | Both controls now measure 148 × 48px on mobile and 164 × 48px above 640px | Playwright DOM measurements |
| Dashboard spacing and heading sizes varied between roles | Shared spacing tokens, title scale, card gaps and padding; Owner filter moved beside its heading; Owner site list and Admin overview received a clearer hierarchy | Four role views inspected at 375, 768, and 1440px; no horizontal overflow |
| Landing visual needed a complete parking-to-outdoor sequence | A Three.js building separates into three parking decks, rotates into an outdoor lot with a 3D car, then reforms and loops; a pause control and static reduced-motion frame are provided | Captured `smartpark-building-1440.png`, `smartpark-split-final-1440.png`, `smartpark-outdoor-final-1440.png`, and `smartpark-return-1440.png` |
| Footer columns had inconsistent proximity, auth pages had bottom whitespace, and Sign In needed compact alternative actions | Footer columns use a fixed responsive grid, auth stage fills the available viewport, and Sign In presents compact Email OTP and Google controls | Sign In inspected at mobile and desktop sizes; Google is disabled until an OAuth flow exists |

The new light and dark foreground, muted, primary and parking-state text pairs measured at least 5.88:1 against their intended backgrounds. Newly styled buttons retain visible keyboard focus through the shared global focus rule. New motion uses transforms or Three.js object matrices and honors `prefers-reduced-motion`.

## Verification and limitations

- `npm run build` passed.
- `git diff --check` passed.
- Playwright checked horizontal overflow at 375/768/1440px, both themes on the public pages, all four role shells, map control sizes and map marker bounds.
- A zoom-in check confirmed all three MapTiler markers retained their geographic anchors and received new projected screen positions. Markers outside the zoomed viewport correctly leave view, as on a standard map.
- The backend was unavailable in this browser run, so authenticated dashboards showed honest API error/empty states. The user will verify live booking, site, account and admin flows against their running backend.
- `npx tsc --noEmit` still reports five pre-existing errors in `GroupedNumberInput`, `UsersTable`, `DriverSupport`, `SiteManagement` and `useSiteManagement`, outside the UI scope of this change.
