## Enhancement A implementation

The public Operations search parses optional `keyword` and `sort`. Keyword trims outer whitespace, folds case and Vietnamese combining accents plus đ/d, matches published site names as literal substrings and has a 100-character post-trim limit. Filtering follows catalogue entry validation and precedes Facility candidate and Payment price reads. Sorting accepts `distance` (default), `price` and `availability`. Ranking occurs after existing filters and delivery freshness. Known zero ranks as known; null or stale ranks last. Distance and site ID break ties. The current and interval price fields remain Payment-owned, and the availability count remains the shared SPARK-273 result.

The protected cursor uses a v2 purpose, binds the normalized filter and sort, and carries the primary rank and a bounded digest for price or availability ranking. The digest covers ordered matching site IDs, primary rank values and distance only. Relevant live ranking changes return `409 SEARCH_CHANGED`. Default distance pagination retains its distance/site ID keyset behavior and no dynamic digest. Older protected cursors require a fresh search.

Touched production files are `DiscoveryHosting.cs`, `SearchFilter.cs`, `ParkingSearchHandler.cs`, `DiscoveryCursor.cs` and `DiscoveryCursors.cs` under the Operations service. Touched test fixtures are `SearchTestOwners.cs` and `SearchTestCapacity.cs`. Added `ParkingSearchEnhancementTests.cs`. No Facility, Payment, reservation admission, chatbot or frontend implementation changed.

## Enhancement B implementation and verification

Operations adds `GET /api/me/discovery/last-booked-location` with the existing Driver role authorization and no-store response. The handler derives Account ID through `AdmissionActor.RequireDriver`, selects one reservation with a non-null `ConfirmedAt` and state `CONFIRMED`, `ALLOCATED`, `PARKING`, or `COMPLETED`, ordered by `ConfirmedAt` descending then reservation ID descending. The EF query is account scoped, no tracking, projects only site ID and confirmation time, and ends with `FirstOrDefaultAsync`. The database read completes before the Facility HTTP request. The query intentionally does not require `RequestId`: the approved historical selection predicates require genuine confirmation evidence and qualifying lifecycle state, and the existing schema allows successful legacy rows without that link.

Facility adds the private `GET /internal/discovery/v1/sites/{siteId}/location` read behind the existing Operations service JWT with dedicated `discovery:site-location:read` permission. It joins the current publication to an active, undeleted site and tenant, checks tenant attribution, and returns site ID, name and valid latitude/longitude. A missing publication or unusable location returns `data: null`; an inconsistent published tenant fails as a dependency error. Operations sends only the site ID, validates the returned contract, and distinguishes authoritative null from HTTP, authorization, routing and malformed-response failures. The public response carries only site ID, name, coordinates and `ConfirmedAt`. No search handler, reservation Saga, payment, schema or frontend changes were made for B.
